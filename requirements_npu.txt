# UniSHARP portable Ascend NPU training environment (Linux only)
#
# This file is for the Ascend NPU launchers. They default to CANN's fused
# meta_gauss_render 3DGS operators and can fall back to the standard-PyTorch
# portable renderer with NPU_RENDERER_BACKEND=portable. Neither path uses
# CUDA gsplat, Triton, 3DGEER, or the CUDA KNN extension in requirements.txt.
#
# ---------------------------------------------------------------------------
# System prerequisites — install these BEFORE pip, not through this file.
# ---------------------------------------------------------------------------
# 1. Huawei Ascend driver + firmware for the target accelerator (for example,
#    Ascend 910/910B), installed by the host administrator.
# 2. CANN toolkit/runtime compatible with both the driver and torch_npu.
# 3. Linux x86_64 or aarch64, a supported CPython release (Python 3.10 is the
#    tested baseline for this project), and a C++ build toolchain for packages
#    that need one.
# 4. In every training shell, initialise CANN first, for example:
#      source /usr/local/Ascend/ascend-toolkit/set_env.sh
#    Use the actual set_env.sh path of the installed CANN release.
#
# The PyTorch, torchvision and torch_npu versions are a matched three-way
# combination with CANN. Do NOT install CUDA PyTorch on this host and do NOT
# blindly install the newest torch_npu wheel. Select the exact versions from
# the Ascend compatibility matrix, then install them BEFORE the packages
# below. Example only (replace with your verified matched versions):
#
#   pip install torch==<TORCH_VERSION> torchvision==<TORCHVISION_VERSION>
#   pip install /path/to/torch_npu-<MATCHED_VERSION>-linux_<ARCH>.whl
#
# Keep these three lines commented: a pinned version here would be wrong for
# any host using another CANN release.
# torch==<MATCHED_TORCH_VERSION>
# torchvision==<MATCHED_TORCHVISION_VERSION>
# torch_npu==<MATCHED_TORCH_NPU_VERSION>

# Fused Ascend Gaussian renderer (recommended)

# ---------------------------------------------------------------------------
# Models and data are not pip dependencies and must be prepared separately.
# ---------------------------------------------------------------------------
# * Prepare public weights and manifests before an offline run with:
#      bash scripts/download_npu_assets.sh
#   This caches UniK3D-ViT-S under UniK3D/checkpoints/huggingface and writes
#   manifests under dataset_manifests. `--assets re10k wildrgbd dl3dv`
#   invokes the respective official download routes after the user has
#   accepted their terms. It does not bypass gated access.
# * `--assets coco-person --coco-person-max-images 5000` downloads a public
#   COCO 2017 person-image subset and box manifest for a future appearance or
#   crop-augmentation stage. It is not a drop-in geometric mixed-training
#   dataset because COCO has no target-view poses or metric depth.
# * The no-review portrait/outdoor recipe uses direct public downloads:
#   Open Images V7 Person, WIDER FACE, CrowdHuman, NeuMan, Nerfies, and
#   optional FFHQ. DL3DV is intentionally not part of this portrait recipe.
#   CrowdHuman and FFHQ have non-commercial terms; check the source licenses
#   before use. The FFHQ 1024px source is ~89 GB and is opt-in with
#   `--assets ffhq --ffhq-download-images`.
# * The portrait NPU launchers can consume the Open Images, WIDER FACE,
#   CrowdHuman, FFHQ, NeuMan, and Nerfies manifests through their matching
#   `*_WEIGHT` environment variables. Use
#   scripts/prepare_calibrated_colmap.py to convert any local COLMAP-text
#   reconstruction to OpenCV w2c/pixel-K rows when you need novel-view
#   supervision.
# * To train exclusively on your own photos, set LOCAL_IMAGES_ROOT before
#   launching either portrait NPU script. It recursively writes
#   local_images.txt and enables the local appearance branch. For real
#   novel-view supervision, set LOCAL_COLMAP_ROOT to a local COLMAP text
#   reconstruction and set LOCAL_MULTIVIEW_WEIGHT=1.0; the launcher converts
#   cameras.txt/images.txt to local_multiview.jsonl automatically.
# * The local portrait NPU launchers enable progressive UniK3D tuning: freeze
#   encoder/decoder first, unfreeze decoder at step 20000, then the final four
#   encoder blocks at step 50000. Set UNIK3D_ENCODER_FULL_UNFREEZE_STEP>0 only
#   for a deliberate final all-encoder adaptation stage.
# * Prepare RE10K with scripts/prepare_re10k_chunks.py when the official
#   release is not already packed. Build the required DL3DV per-image depth
#   tree with scripts/prepare_dl3dv_unik3d_depth.py on the NPU.
# * Set DATA_ROOT_RE10K, DATA_ROOT_WILDRGBD, DATA_ROOT_DL3DV, and
#   DATA_ROOT_DL3DV_DEPTH for the mixed NPU launcher.
# * Set DATASET_MANIFEST_DIR to the directory containing
#   re10k_train_chunks.txt and the other UniSHARP manifests.
# * Verify fused rendering after CANN and the custom wheel are installed:
#      python scripts/check_npu_env.py --require-meta-gauss-render
# * Then launch the NPU scripts normally. They use `ascend_fused` by default;
#   set NPU_RENDERER_BACKEND=portable only for fallback/debugging.
